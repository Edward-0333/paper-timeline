# 每篇论文一个资料文件夹

当前文献库采用版本 2 结构。每篇论文在 `papers/` 中拥有独立的资料文件夹，原文、笔记、标注、全文解析结果和引用记录集中存放；无 PDF 的文献也有自己的文件夹。

```text
library/
├─ library.json                         全库索引，version: 2
├─ library.json.bak                     上一次索引保存的备份（如有）
├─ AI-INDEX.md                          AI 资料导航入口（自动生成）
├─ ai-index/catalog.json                按标题、编号、标签定位论文（自动生成）
├─ papers/
│  ├─ Alvinn__a1b2c3d4e5f6/
│  │  ├─ paper-index.json               本篇元数据和资料清单（自动生成）
│  │  ├─ original.pdf                   PDF 原文（如有）
│  │  ├─ notes.md                       Markdown 阅读笔记（如有）
│  │  ├─ annotations.json               标注、页码和缩放（保存阅读记录后生成）
│  │  ├─ annotations.json.bak           上一版阅读记录（如有）
│  │  ├─ chat.json                      已保存的 AI 对话和资料引用（如有）
│  │  ├─ chat.json.bak                  上一次对话记录（如有）
│  │  ├─ parsed/                        MinerU 全文转换（如有）
│  │  │  ├─ result.json                 当前成功解析版本的索引
│  │  │  └─ <转换版本UUID>/              全文 MD、JSON、图片
│  │  └─ citations/                     引用监控记录（如有）
│  │     └─ citations.json
│  └─ 另一篇论文__b2c3d4e5f6a7/
└─ sync/                               全库账户绑定及同步状态（如有，无凭据）
```

资料文件夹默认以「简短标题＋`__`＋论文 ID 前 12 位」命名，遇到重名会延长编号部分。名称创建后保存在论文的 `storageFolder` 字段中，修改标题或重新检索元数据不会重命名文件夹。导入 PDF 时尚未完成标题检索，文件夹名称可能沿用导入时的名称；以索引关联为准。不要手工重命名该文件夹或 `original.pdf`、`notes.md` 等软件管理的文件。

根目录的 `library.json` 继续保存完整论文 ID、元数据、标签、评分、分类、时间线和文件关联。论文 ID 和 PDF 内容哈希保留原含义，哈希继续用于去重及校验原文；不依赖文件名识别重复原文。界面左侧用于分类的「文件夹」是逻辑分类，与这里的磁盘资料文件夹不同，修改分类不会搬动资料。

## 查找与 AI 工作目录

PDF 阅读页顶部也可直接打开资料文件夹。供外部 AI 分层读取的入口是 `AI-INDEX.md → ai-index/catalog.json → papers/<资料文件夹>/paper-index.json`，内部使用库根目录相对路径，自动维护但不替代 `library.json` 主记录。桌面复制会携带各篇索引，目标库启动时重新生成根入口和目录；手工复制完整库时三层一起保留。详见 [AI 资料导航](library-ai-index-guide.md)。

在文献详情「更多操作 → 打开资料文件夹」可以直接打开当前论文的文件夹。AI 接口 `papers.get {id}` 返回 `directory`，表示该论文资料文件夹的实际绝对路径；`pdfPath` 仍是原文绝对路径，没有 PDF 时为 `null`。操作名称和参数不变。

从 PDF 阅读器进入 AI 聊天时，`workingDirectory` 绑定当前论文的资料文件夹。每次发送和重试时重新查询，搬库后使用新位置。论文阅读 Agent 通过工具按需读取当前论文的全文、笔记、标注与解析图片，或渲染原始 PDF 页面，再将这些内容发送到配置的模型。缺少全文时可调用本机 MinerU 并等待；不允许任意目录访问、命令执行或修改原始资料。成功对话、工具步骤和资料引用保存在 `chat.json`，不保存图片二进制或原始工具结果；复制完整论文文件夹即可保留。详情见 [论文 Agent](model-api-guide.md)。

可以在论文资料文件夹中另存补充材料、自己的分析文档等普通文件，桌面复制文献库会一并携带并校验。这些额外文件不会自动成为列表附件，也不会自动发送给聊天模型。

## 旧库自动升级

新版启动并打开版本 1 的文献库时，先完成目录升级，再向界面和后台任务提供该库；不需要手工搬动文件。

1. 检查原索引与资料目录，拒绝文件链接和冲突目标，保留源文件。
2. 将原索引原样备份为 `library.pre-paper-folders-v1.json`。
3. 把旧 `pdfs/`、`notes/`、`annotations/`、`parsed/`、`citations/` 中属于各论文的资料复制到对应的新目录，保留标注和解析备份、全部解析版本及引用历史。先暂存，再逐文件进行 SHA-256 校验。
4. 全部复制和校验成功后，才原子替换 `library.json`，切换到版本 2。论文 ID、元数据、标签、评分、分类、时间线、监控及阅读记录保持关联。
5. 成功后清理本轮已校验的迁移暂存副本。不能确认安全清理的内容会保留，不影响已经提交的新库。

迁移不会删除旧的五类资料目录，也不会删除原索引备份；它们留在原库中用于恢复，不再作为新版的活动资料。升级需要额外磁盘空间，之后的新编辑只写入 `papers/`。旧目录中无法关联到论文的文件仍留在原目录，不会被悄悄丢弃或强行归属。

如果迁移在索引提交前失败，旧索引和源资料保持不变，软件报告失败并停止打开该库。处理磁盘空间、权限或冲突后可重试，已经复制且校验一致的文件会复用，不覆盖不同内容。恢复时需要同时核对索引和对应布局，不要在软件运行中直接用旧备份覆盖新版索引。

## 复制与换电脑

优先使用「文献库设置 → 复制当前文献库到新位置」。版本 2 的桌面复制包含当前索引及可用的版本 2 索引备份、`papers/` 下每篇在库论文的完整资料文件夹（包括额外普通文件、各篇备份及全部解析版本）和 `sync/`，逐文件校验后使用新位置。如果普通索引备份仍是旧版格式，目标库改用当前索引作为备份，避免备份指向未复制的旧目录。它不会再复制旧布局的历史目录、升级前索引备份、迁移暂存目录或临时接口凭据，源库中的恢复资料仍保留。

手工搬库前先退出软件，再复制完整文献库；这样也会带上原库的历史备份。新电脑在「文献库设置」选择库目录，云端账户重新登录，大模型配置重新填写；MinerU 环境与模型需另行安装。不要同时修改同一库在两台电脑上的独立副本。

开发验证使用独立测试库。目录迁移、重试、冲突保护、资料完整性、重启和复制后的路径由单元测试覆盖；阅读器、聊天和 MinerU 使用各自桌面回归测试验证。正式库不得用作测试夹具。

源码维护时也可显式执行离线迁移，使用与桌面启动相同的迁移服务。先关闭使用该库的程序，在源码目录执行 `node --import tsx scripts/migrate-paper-folders.ts --library "完整文献库路径"`。此命令不启动云同步、元数据检索或大模型，不读取账户配置；遇到桌面会话文件或未完成检索时停止。普通用户直接打开新版软件即可。
