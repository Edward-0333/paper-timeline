# 云端引用监控：使用、升级与验证

实现日期：2026-10-21。本次修改覆盖本地 Paper Timeline 与同级 paper_monitoring 源码；是否已经部署服务器须以部署记录和在线接口验证为准。仅替换桌面 EXE 不会升级远程 Django 服务。

## 使用

连接状态与同步结果分开显示：网络不可达显示「连接失败」，账户过期显示「需重新登录」；账户已验证但本地引用校验、保存或服务器数据处理失败时，显示「已连接，同步失败」。首页和连接弹窗显示具体错误及相关论文；同步概况保留上次完整同步数据，不把失败当成新一轮成功。

可向文献库助手提问「诊断云端引用监控为什么失败」，或执行 `PaperAI.cmd call cloud.diagnose`。诊断仅 GET 验证现有账户并检查登记引用 JSON，不同步、不更改开关、登录会话、原文件或备份。默认每页检查 20 篇，按 `local.nextOffset` 继续，`limit` 最大 100；`checkConnection:false` 可仅检查本地。连接检查是当前结果，`status.failure` 是最近同步失败记录，可能已经过时。诊断返回论文、相对文件路径、异常字段和原因，不返回凭据或整篇引用内容。

历史引用缺少 `year` 时按未知年份 `null` 兼容读取，不重写原文件；后续同步正常保存会规范化年份并保留上一版备份。下载、读取和保存采用一致的记录校验，年份字符串、非整数或损坏来源等仍会明确报错，不丢弃该条引用或用空列表覆盖。

1. 打开个人首页，「API 大模型」与「云端引用监控」为两个并排小卡片，窄窗时上下排列。点击云端卡片的「登录并连接」，在「连接云端引用监控」弹窗中填写运行新版 Paper Monitoring 的 HTTPS 基础地址，用现有账户登录，成功后弹窗关闭。地址不包含 `/api/desktop/v1`。首页显示连接状态及账户摘要，不再常驻登录表单；已登录后可点击「管理连接」打开同一弹窗，立即同步或退出登录。关闭弹窗不会退出账户或停止同步。
2. 进入文献库，在论文详情开启引用监控。首页的“待同步开关”归零表示服务器已接收；抓取结果在后续同步中出现。
3. 服务器按全部有效用户订阅去重，每天北京时间 08:00 开始逐篇抓取，每篇完成后默认等待 10 秒再处理下一篇。桌面运行且登录后每分钟同步，也可点击“立即同步”。来源限流、分页或网络耗时会使完成时间延后。
4. 退出桌面登录、关闭软件均不会关闭云端任务。要停止某篇的监控，先关闭其开关并完成同步。其他库或账户订阅同篇时，共享抓取继续。
5. 旧本地监控仍显示待迁移数量，在连接管理弹窗中点击“迁移到当前账户”后才上传订阅，不因打开弹窗自动迁移。原引用 JSON 不删除、不覆盖用户 PDF/MD。

文献库及首页分类列表的「被引数」为本地已同步、去重后的引用文献数量。点击数字（包括 0）会在顶部打开「引用详情：论文标题」标签，显示引用该论文的文献，每页 50 条，可翻页并单击条目查看作者、日期、期刊或会议、DOI/arXiv、来源和摘要。同篇复用已有标签，各篇分别保留页码及选中条目，直到关闭或退出软件。尚未取得有效数据的「—」不可点击。

引用列表读取本地缓存，断网或关闭监控后仍可查看历史结果。「刷新列表」只重读本地文件，不向服务器请求抓取；要取得服务器最新结果，请先在个人首页同步。读取失败会显示错误及重试按钮，不清空已有文件。引用列表可与 PDF 阅读及首页分类标签共存，切换前会等待 PDF 标注保存。

对感兴趣的引用文献，点击该行「加入文献库」，先显示「是否确定加入文献库？」确认框及该论文标题。只有点击「确认加入」才将本地引用记录中的标题、作者、发表信息、编号和摘要保存为一篇无 PDF 文献，位于「未分类」，状态为「待核对」；默认聚焦「取消」，取消、Esc、关闭或点击弹窗外部均不添加。已存在的论文显示「已入库」标记，重复点击或在另一篇论文的引用列表中再次添加时会复用已有记录，保留原有资料、分类、标签和评分；匹配有歧义或编号冲突时提示核对。添加成功后可回到文献库补充原文、笔记等资料。

加入操作仅保存已有书目信息，离线可用，不运行在线元数据检索、不下载 PDF、不自动开启该论文的引用监控。服务器同步、翻页与刷新引用列表均不会自动将引用条目加入文献库。本功能通过受主窗口检查的桌面 IPC 提供，不新增公开 AI 操作。

个人首页的论文统计针对整个当前库。服务器最近成功抓取是当前账户有效监控中最近的成功来源时间，不表示全部来源成功。本地最近完整同步只在所有本轮请求成功且数据保存后更新；分页失败保留已保存页并重试，引用会去重。新增引用按本轮成功同步前后去重数量计算，不按多条被引关系重复计数。

「同步概况」改为图表与数字卡：本库云端已确认和账户全部监控按同一尺度绘制水平柱状图，均按论文去重计篇；云端待抓取与未完整更新单独绘制，分别对应服务器当前排队状态和部分或全部来源失败状态。它们不表示每天这一轮的完成进度，也不通过总数减法推算成功论文数；正在抓取及已安排下次抓取的论文可能不计入待抓取状态。新增引用、本库待同步开关、旧网页待处理分别显示重点数字，旧网页数量按订阅条目计项，不与论文数量相加。最近抓取与本地完整同步保留独立时间记录。尚未取得或旧服务器未提供的字段显示占位，不能当作零；离线或退出登录后保留上次同步记录并说明缓存状态。

## 监控清单对账（2026-10-22）

个人首页区分本库本地开关、本库云端已确认监控、账户全部云端监控，以及旧网页待处理订阅。
账户全部统计含旧网页和其他文献库，并对同一论文去重；它不必等于当前库的数量。

登录后点击“检查监控差异”。“按本库开关对齐”会补交当前库缺失或版本/开关不一致的订阅，
并暂停当前库在本地找不到对应订阅的云端项目。只处理当前库，其他来源继续保留。
这是一项明确操作，日常同步不会自动覆盖较新的云端版本，也不会按本地缺失自动删除任务。
旧本地监控仍需原有的“迁移到当前账户”，对账不会默认上传它们。

下方分页显示当前账户旧网页的有效订阅，每页 20 条。“转入本库”先保存在本地，再将本库
订阅开启与旧订阅停止作为同一服务端事务提交；网络断开、响应丢失或软件重启后继续重试。
已匹配的本地论文保留附件、笔记、标签、评分和元数据；只有可靠编号或明确书目匹配才关联，
多条候选或编号冲突需先核对。无法匹配时新增无 PDF 条目，缺失日期保留空，不下载全文。
“停止旧订阅”只停止所选旧来源，并同步旧 Paper 的开关，防止再次运行迁移命令时恢复。
原论文、引用和私人阅读数据保留；其他库或账户仍订阅时，服务器继续共享抓取。

AI 可调用 cloud.review {offset?} 查看真实 id/revision，再按用户明确范围调用
cloud.reconcile、cloud.importLegacy {id,revision} 或 cloud.stopLegacy {id,revision}。
停止旧订阅需要联网；版本已变化会提示刷新。导入已保存但尚未同步时显示待处理错误，
不要通过修改存储文件清除队列。

本功能需两端升级。旧服务器的正常同步不受影响，桌面会提示先升级对账服务；不发送
新格式的转入请求，避免旧服务忽略迁移参数。服务端无需新增数据库迁移，但须部署新版后端、
重启专用 Web 服务；新版网页统计说明需要重新构建前端。每日 08:00 调度与间隔保持原设置。

## 本地数据与登录

`sync/cloud.json` 保存稳定库 UUID、服务器与账户 ID、订阅确认版本、每篇已完成引用版本。`papers/<资料文件夹>/citations/citations.json` 沿用旧格式并合并历史；目录由论文的稳定 `storageFolder` 关联。整库复制包括完整 `papers/` 和 `sync/`；程序复制前会等待同步停止并校验文件。旧版目录升级保留论文 ID、订阅和引用历史，不重新注册监控或重新抓取，服务器接口和调度不受目录变化影响。新版复制不携带旧布局历史备份，原库中的恢复资料保留。详见 [文献库布局与迁移](library-layout-guide.md)。

密码不保存。90 天可撤销桌面令牌只在主进程内使用，经 Electron safeStorage 操作系统加密保存在本机用户目录的 cloud-sessions 文件夹；不传给渲染页或 AI API、不写入库。系统加密不可用则拒绝保存登录。换电脑须重新登录同一账户。库已绑定账户后拒绝其他账户或服务器，使用独立库可连接另一个账户。

同一个库的拷贝适合换电脑，不支持两台机器同时编辑独立副本；服务器拒绝陈旧开关覆盖，并显示版本冲突。退出时若服务器离线，会明确提示远程会话未撤销，可在网页“服务概览”中撤销该设备。

## 服务器部署顺序

在现有项目的发布机制下部署，保留原数据库、配置和历史数据。生产环境需 HTTPS，客户端只允许远程 HTTPS 或本机回环 HTTP。

1. 备份数据库与当前发布版本，停止旧的 citations timer / service 及任何旧 `monitor_citations` 进程。等待旧抓取退出，避免并行使用旧、新调度。
2. 发布新版 backend 和 frontend/dist。使用现有虚拟环境和服务器环境配置运行 `python manage.py migrate`。
3. 运行 `python manage.py migrate_cloud_monitors`。此命令可重复执行，将旧用户监控及公共引用缓存映射到共享表；保留原 Paper、UserCitation、阅读状态、笔记、收藏和 AI 结果。日志中需人工核对的记录保留原样。
4. 安装本项目更新后的 `deploy/systemd/paper-monitoring-citations.timer`，执行 daemon-reload 并启动 timer。timer 每天北京时间 08:00 启动到期队列，逐篇处理并持久化每日到期时间、论文间隔和租约。同步安装更新后的 service（允许长时间运行）。不要同时启动旧版 worker。
5. 重启新版 web，确认 `/api/desktop/v1/me` 未登录返回 401，网页登录后服务概览可打开，再由用户在桌面正常登录。

旧 `fetch_citations --force` 入口仍接受参数，但不会绕开共享队列的间隔和租约。旧网页手动刷新接口仅登记共享任务并返回 202，不再逐用户抓取。新监控不会进入自动 AI 任务队列，也不下载 PDF。

全局表位于新增 `cloud` Django app，原 papers 表不删除。共享快照 CitationBatch 不可变，签名分页游标固定到具体批次并验证账户、库和订阅版本，避免分页中混入新批次；历史批次暂不自动清理，后续可根据存储规模制定保留策略。

## 每日抓取与限速设置（2026-10-21 调整）

服务器恢复每天北京时间 08:00 开始一轮，不再每 10 分钟轮询外部数据库。新增论文在下一次 08:00 处理；其他账户后来订阅同一论文时可同步已有缓存，不重置抓取时间。桌面约每分钟同步服务器已有结果的频率保留。

服务器环境配置可调整间隔：

```dotenv
PAPERS_CITATION_PAPER_INTERVAL_SECONDS=10
PAPERS_CITATION_REQUEST_INTERVAL_SECONDS=1.1
```

前者是上一篇处理完成后到下一篇开始的等待秒数；后者是同一来源连续请求的最小开始间隔，包括分页。遇到 429 仍按已有机制等待重试，间隔不能保证外部数据库始终不限流。配置修改后重启抓取服务生效。

队列使用共享租约防止多个进程同时抓取，论文间等待时间也会保存；重启后继续未完成任务，已完成论文等到下一天 08:00。长队列会继续执行到完成，因此论文较多时，后面的论文会晚于 08:00 更新。service 已设置无限启动等待时间，允许整轮长时间运行。

升级时执行新增的 cloud/0002 迁移，既有任务将调整到每日时刻；保留原引用数据。线上未部署新版前仍按原服务器程序运行。

## 开发验证

桌面：`node scripts/run.cjs test`、`node scripts/run.cjs build`、`node tests/citation-monitor.cjs`、`node tests/timeline-viewport.cjs`。

服务器：backend 下 `python manage.py test --noinput`，`python manage.py makemigrations --check --dry-run`。frontend 下 `npm ci`、`npm run build`。

测试使用独立本地库及 Django 测试数据库，不修改正式文献库；模拟提供商验证分页、部分失败、身份隔离、共享抓取、租约和历史迁移，不把模拟结果当成真实论文引用。

## 当前边界

- 未识别 DOI/arXiv 且作者、年份不足的论文分别保留，避免仅按相似标题合并。多个强编号指向不同已建任务时拒绝自动合并，需核对编号。
- 结果变化以每篇不可变批次同步，首次订阅可立即取得服务器已有缓存。每个新批次传完整累计结果并在本地合并；不做逐字段差分传输。
- 暂不支持 PDF/MD 云备份、自动下载、自动评分和全文 AI 分析。
